# Model observation field guide

Create an entry only for an observed run, under a registered exact-model key.

- Identity: provider, exact model ID, alias resolution if known, tool and version.
- Date and scope: task, settings, relevant input revision.
- Observation: what happened; distinguish output from interpretation.
- Evidence: reproducible example or local result path without secrets.
- Limit: other explanations and conditions under which the observation fails.
- Action: narrowly scoped workaround, if justified.
- Recheck: model/version/configuration change or contradictory result.

Keep operational outcomes, not private reasoning traces. Promotion into shared
project facts requires independent evidence about the subject, not model behavior.
